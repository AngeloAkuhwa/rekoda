## 5. Capability detail

### 5.1 Product foundation and configuration — VERIFIED COMPLETE

- **Evidence:** `apps/api/src/config.ts` (1,069 lines) with `config.test.ts` (53 cases); boot doctor called from `apps/api/src/main.ts` with its logic in `packages/db/src/repos/boot-checks.ts` (refuses a DB role that can bypass RLS; enrols and checks `VAULT_KEY` and `MATCH_KEY` fingerprints, migration 0120); `scripts/check-boundaries.mjs`.
- **Works:** every numeric env value is parsed fail-closed (blank, hex, exponent and sign forms refused; zero is a legal kill switch); an unrecognised `NODE_ENV` is treated as production; `FX_MODE=live`, `REKODA_REVEAL_OTP` and `REKODA_OPERATOR_SECRET` refuse to boot in production; a media flag set without its provider key refuses to boot; Fastify hardening (body limit, raw body for HMAC, 411/413 pre-parse guards on webhook paths, per-IP rate limit, CORS allowlist, version headers on every response).
- **Not yet:** there is no ESLint (lint is Prettier); the per-IP limiter is in-memory per process; `packages/shared` has no tests; `packages/db/migrations/meta/` holds stale drizzle snapshots for 0000–0003 only.
- **Configuration drift:** six names in `.env.example` are read by no code: `SESSION_SECRET` (sessions are opaque hashed tokens), `APP_URL`, `PAYSTACK_PLAN_CHAT`, `PAYSTACK_PLAN_INTEGRATE`, `PAYSTACK_PLAN_COMPLETE`, and `OWNER_DATABASE_URL` (migrations read `DATABASE_URL`, so following the example literally runs migrations as the app role and fails). `MONO_SECRET_KEY`, `MONO_BASE_URL`, `REKODA_SHOP_ORDERS_PER_HOUR`, `REKODA_TRANSFER_VERIFY_MIN_SECONDS`, `REKODA_PLAN_CATALOGUE_READS` the fourteen `REKODA_COMMAND_*` flags, `NEXT_PUBLIC_MONO_PUBLIC_KEY` and `NEXT_PUBLIC_REKODA_WHATSAPP` are read by code and not documented. The environment inventory for staging is in `REKODA_LAUNCH_READINESS.md` §11.1.
- **Local note:** the four guard scripts that compute `ROOT` via `new URL(..).pathname` fail on a Windows path containing a space; CI on Linux is unaffected.

- **Evidence:** `packages/core/src/billing.ts` (ADR 0024 arithmetic); migrations 0020, 0042, 0112, 0113; `apps/api/src/billing/{renewal-sweep,grace-sweep}.ts`; `billing.process` split from `payment.process` in the pump so Rekoda's revenue never meets a merchant's ledger; `subscriptions`, `charges`, `billing` integration suites.
- **Works:** cycles, charges, proration, packs, grace ladder (reminders on days 1 and 5, then read-only with the books intact); §47 refuses a paid plan change before opening a charge; a partial payment does not unlock a plan, an overpayment does.
- **Not yet:** there is no card-on-file, so every renewal opens a charge and immediately enters the grace ladder by design (`renewal-sweep.ts:134-137`); the billing page then shows "A payment did not go through" for a payment that was never attempted, which is the wrong sentence; `addOnsRepo.hold` and `endHolding` have zero production callers, so the Developer API Starter and extra-seat add-ons cannot be sold; the billing page status map lacks `paid`; a legacy operator plan-change path bypasses `applyCycle`; Paystack subscription plan codes (`PAYSTACK_PLAN_*`) are documented and unread.

### 5.28 Usage metering and provider-cost tracking — VERIFIED COMPLETE (consumables) / IMPLEMENTED, NOT LIVE-VERIFIED (costs)

- **Evidence:** `consumeUnit` single-statement atomic enforcement with refunds; `UNIT_KIND` (OWN-1) and the boundaries guard that refuses a capacity unit in a meter call; `usage_events`; `platform_cost_events` (0107, app holds INSERT only); `GET /v1/ops/margin?period=`; `packages/core/src/ai-cost.ts` and `messaging.ts`; `usage`, `quota`, `api-metering`, `tenant-fk-platform-costs` suites.
- **Not yet:** capacity enforcement half-built (`PAYMENT_CONNECTIONS` unlimited); `PAYMENT_FEE`, `BANK_FEED`, `STORAGE`, `TELEPHONY` cost classes have no writer and the OTP template cost is only logged, so margin understates cost; the margin engine sums `amount_minor` across a free-form currency column (safe only while the one writer hardcodes NGN); no staleness guard on the Meta price card dated 24 Aug 2026 with a repricing on 1 Oct 2026.

### 5.29 Notifications — PARTIAL

WhatsApp is the only channel: replies, documents, OTP, billing and retention templates, graduation nudge. No email and no SMS exist anywhere, so sign-in has a single point of failure. The graduation nudge sends free-form text outside the 24-hour window with no template and will be rejected by Meta (131047) and swallowed.

### 5.30 Queues, workers, sweeps — IMPLEMENTED, NOT LIVE-VERIFIED / PARTIAL

- **Evidence:** in-schema job queue (ADR 0022, migration 0004; `rekoda_worker` is the only role that reads across tenants, and only to claim); `runner.ts` with `REKODA_WORKER_CONCURRENCY` lanes and per-business serialisation; outbox (0060) and dispatcher; one entrypoint `apps/api/src/main.ts`, `REKODA_WORKER=1` makes a process poll the queue as well as serve HTTP; thirteen `setInterval` sweeps registered in `jobs.module.ts` (pump 2 s, outbox 2 s, webhooks 5 s, stranger 20 s, transfers 120 s, settlement 600 s, bank feeds 1,800 s, catalogue, grace, renewal, recurring and depreciation 3,600 s, retention 21,600 s), leader-elected per business by advisory lock; `jobs`, `outbox`, `idempotency` suites.
- **Not yet:** no external cron; no separate worker entrypoint; no sweep fires an immediate first pass and no last-run is persisted, so a replica restarted more often than every six hours never runs retention; `outbox_events` has no backoff column and `claimBatch` no time predicate, so a transiently failing event is dead in about fourteen seconds; `sinceReclaim` in the runner advances only when the queue is empty; `oldestPendingSeconds` uses `run_at`, so a retry backlog reports as healthy; no pruning of done jobs, dispatched outbox rows, idempotency records, expired challenges or counter tables.

### 5.31 Retention and deletion — IMPLEMENTED, NOT LIVE-VERIFIED

- **Evidence:** `apps/api/src/privacy/retention-sweep.ts` (warn, erase, evidence, object deletions); the delete is a `SECURITY DEFINER` function that re-checks its own due-date predicate and discovers tables from `information_schema`; R2 deletions are real and `NoStorageConfigured.delete()` rejects rather than lying; `/privacy#retention`, `/data-deletion`; `docs/runbooks/data-erasure.md`; `retention-sweep.integration.test.ts` (21), `retention.integration.test.ts` (16).
- **Not yet:** `META_RETENTION_TEMPLATE` unset means the sweep warns nobody and deletes nothing (by design); the WhatsApp erasure fires on ten phrases, the second ask has no time window, and `eraseDataWork` deletes only `customer_identities` (the account and suppliers stay, blobs remain); `financialYears = 6` and `conversationDays = 90` are published on `/privacy` and enforced by nothing; evidence-retention clocks have no writer producing the state they need; the retention sweep sends and bills the template before claiming, so a crash re-sends; the erasure runbook's SQL selects the wrong column into `business_id`.

### 5.32 Audit trail — IMPLEMENTED, NOT LIVE-VERIFIED

Append-only by GRANT (no triggers), proven through the real non-owner roles; every financial write, membership change and operator action names its actor; `GET /v1/reports/audit(.csv)` (owner, accountant). ### 5.37 Backups and PITR — NOT IMPLEMENTED (as code)

A real restore drill runs in CI (`recovery-drill.integration.test.ts`: `pg_dump`, `pg_restore`, invariants). No backup mechanism exists: no script, timer, compose service or WAL archiving. `docs/runbooks/backup-restore.md` says so honestly and plans nightly `pg_dump`, which contradicts accepted ADR 0010 (continuous WAL archiving, RPO in minutes, a `scripts/restore-drill.sh` that does not exist).

### 5.38 Deployment and runtime — NOT IMPLEMENTED

There is no `Dockerfile`, no production compose file and no Caddy configuration in the repository; `docs/runbooks/deploy.md` prescribes Hetzner + Docker Compose + Caddy behind Cloudflare, every step in prose, and names `migrate` (drizzle-kit) where the real path is `migrate:apply`. `docker-compose.dev.yml` runs Postgres 16 only. The API binds `0.0.0.0` and requires `REKODA_TRUSTED_PROXIES` in production. Nothing in the repo establishes TLS termination or whether `/v1/ops` and `/health` are internet-reachable.
