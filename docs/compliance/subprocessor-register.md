## What is deliberately NOT sent anywhere

- Raw voice audio is never persisted and never placed in logs or error
  messages; it is fetched, probed for duration, sent once to the
  transcriber and discarded (ADR 0032).
- Customer identities are AES-256-GCM ciphertext in the vault; no
  provider receives vault plaintext. Model prompts carry meaningless
  tokens in place of supported identifiers (recorded customers, phones
  and emails). Three exceptions, all in the rows above: a customer name
  nobody recorded, first met in a record request, reaches Anthropic's
  interpretation model as typed until it is vaulted and tokenised
  (ADR 0005 layer 3, Amendment 1 case 4; an exception to spec C.3 ratified by OWN-106, under case 3's limits: Anthropic only, at most two calls, no log or telemetry field, no new store); a customer name nobody
  recorded, in a read-only question, reaches Anthropic as typed and is
  not vaulted (ADR 0005 Amendment 1 case 3, OWN-102(5)); and the high-value
  verifier's text can hold such a name for OpenAI, so production
  refuses to start with the verifier configured until OD-63(c) is
  ruled.
- No analytics or advertising processors exist at launch. Adding any
  provider to production means adding a row here in the same PR.

## Change discipline

A new provider, a removed provider, or a change in WHAT an existing
provider receives is a change to this file in the same pull request, plus
a review of `data-transfer-assessment.md` and the public `/privacy` and
`/ai-privacy` pages. The register drifting from the code is the failure
mode this file exists to prevent.
