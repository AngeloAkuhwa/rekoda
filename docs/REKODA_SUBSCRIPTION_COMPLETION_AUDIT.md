# Rekoda subscription completion audit

> **Status of this document:** engineering audit, 2 November 2026, against `main`
> at the SHA recorded in `docs/HANDOFF.md`. Evidence is the repository: source,
> tests, migrations and the canonical documents. **No staging system, GitHub
> Actions staging run or provider dashboard was inspected for this audit**, and
> no payment was made. Where a statement rests on a canonical document rather
> than on source read during this audit, it says so. It changes no owner decision.
>
> **Updated 4 November 2026:** the automated-evidence column now names the browser journeys
> (renewal paid, monthly and yearly; a cancellation kept and one left to run), added after a
> requirement-by-requirement gap check of SUB-03 and roadmap P1-3. Browser journeys run against a
> stand-in Paystack with states written to the database; they are CI evidence, not staging
> acceptance, and no status in the Staging or Provider columns changed.

## Verdict

**The subscription workflow is NOT 100% complete, and it must not be described as
complete.** The code covers most of the lifecycle and is well tested against
test doubles, but: no real Paystack transaction has ever run (G-05, gated on the
written Paystack platform-model confirmation, §47), nothing since mid-October is
staging-accepted, renewal has no card on file by design (every renewal is a new
payment the merchant must make), annual billing is built and launches by owner ruling (OWN-40) but is switched off
by a flag until launch configuration turns it on, the Day 0 welcome is not
built, and the Meta templates the billing and trial messages need are not
approved.

Status words used below, never collapsed: NOT BUILT, PARTIAL, CODE COMPLETE,
TESTED (automated), MERGED, DEPLOYED TO STAGING, STAGING ACCEPTED, PROVIDER
VERIFIED, PRODUCTION READY.

## What must be true before this can be called complete

1. Written Paystack platform-model confirmation (§47) and one controlled real-money drill (owner, external).
2. A staging acceptance run of the whole lifecycle on Paystack **test mode**: first purchase, duplicate and replayed webhook, partial and over-payment, failed renewal into grace, expiry, reactivation, pack purchase, annual (flag on), and the trial Day 0/7/13/14 boundaries with a controlled clock.
3. Meta approval of the billing and trial templates, then one real send to a test number.
4. Annual sales switched on in the launch configuration (OWN-40) and accepted on staging.
5. A DB-level control for the plan columns (see the #396 recommendation) before public launch.
6. ~~An explicit test that subscription money never enters the merchant books.~~ Done: the SUB-04 gap check (2 Nov 2026) located four such tests (see the Ledger separation row).
7. An owner decision on card-on-file or auto-debit renewal (post-launch is acceptable if stated).

Nothing above is a reason to doubt the existing code; it is the difference between
CODE COMPLETE plus automated tests and a lifecycle that has been proven with a
real provider and real messages.
